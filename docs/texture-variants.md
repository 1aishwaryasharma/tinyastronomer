# Texture and model delivery tiers

Decision record for the Nov 2026 UX review, item 3 ("shrink what the 3D
scenes download"). Measurements are file sizes on disk (bytes on the wire are
the same: the dev server and Cloudflare serve these files uncompressed).

## What the Light Study really downloaded

The review measured 2.49 MB for the home Light Study. That figure left out
`vendor/three/three.core.min.js` (385 KB), which `three.module.min.js` imports,
so the real first-open payload was about 2.88 MB.

| Asset | Before | Laptop now | Phone now |
| --- | ---: | ---: | ---: |
| three.module.min.js + three.core.min.js + common.bundle.js | 802 KB | 802 KB | 802 KB |
| Earth day map | day-4k.jpg 473 KB | day-4k.jpg 473 KB | day-2k.webp 238 KB |
| Earth night lights | lights-2k.webp 306 KB (lossless) | same | lights-1k.webp 43 KB |
| Earth normal map | normal.jpg 337 KB | normal-2k.webp 220 KB | normal-1k.webp 56 KB |
| Earth specular map | specular.jpg 223 KB | specular-2k.webp 132 KB | specular-1k.webp 44 KB |
| Earth clouds | clouds-1k.png 260 KB | clouds-1k.webp 189 KB | clouds-512.webp 53 KB |
| Moon color | color-2k.jpg 458 KB | color-2k.webp 315 KB | color-1k.webp 86 KB |
| Moon height | height-1k.jpg 112 KB | height-1k.webp 68 KB | height-512.webp 22 KB |
| **Total** | **2.88 MB** | **2.50 MB** | **1.34 MB** |

The phone tier is chosen by `prefersCompactTextures()` in `earth-visuals.js`:
`(max-width: 820px), (pointer: coarse)`, the same breakpoint the chrome uses
for the phone layout. Measured in the browser against the dev server on
2026-11-09: laptop 2,559 KB and phone 1,344 KB for the scene resources
(including the home preview image).

The phone target in the review was "under about 1.2 MB"; with the Three.js
runtime counted honestly, 1.34 MB is the result. Going lower means shipping a
smaller Three.js build or dropping the 2K day map on phones, both out of
scope here.

## Encoding choices

Generated by `tools/build-texture-variants.py` (Pillow, WebP method 6).

- Lossless WebP was tried first for the normal map and clouds and is larger
  than the JPEG and PNG sources (normal-1k lossless 428 KB vs 56 KB lossy), so
  every derivative is lossy. The night-lights 2K map stays the existing
  lossless file; its 1K phone version is lossy q90 over a black background.
- Normal map q90, specular q85, clouds q85 with alpha q80, Moon q85. Quality
  85 vs 90 on the Moon color map is 315 KB vs 426 KB with no difference visible
  at the Light Study's closest zoom.
- Checked on screen (Chromium, dev server, 1280×800 and 390×844): the Earth at
  default framing and at the closest zoom, day side and city lights, with the
  cloud shell. The 2K tier is indistinguishable from the sources. The 512
  cloud map on the phone tier is visibly soft only at the very closest zoom;
  at the default and middle distances it reads the same. Swapping phones to
  clouds-1k.webp costs 136 KB if that softness is judged too much.
- The JPEG and PNG sources stay in the repository as the record of what NASA
  and three.js published, and so the derivatives can be regenerated.

## Home preview

`home-preview.webp` (922 px) is shown at about 290 px on phones and 486 px on
laptops. `srcset` now offers 320, 480 and 720 px versions (16, 28 and 47 KB);
a 390 px phone picks the 320 px file at 1× and the 720 px file at 3×.

## Planet models

The nine NASA GLBs were already quantized with 2K WebP textures. Geometry made
up about 1.2 MB of their 2.57 MB; textures the rest, Mercury's 493 KB surface
composite being the largest single item.

- Meshopt (`gltf-transform meshopt --level medium`, `EXT_meshopt_compression`)
  packs the quantized attributes exactly, so nothing about the surfaces
  changes. Total 2,572,920 → 1,919,336 bytes (−25%). Per model: Ceres 651→464
  KB, Pluto 489→302 KB, Neptune 117→61 KB, Uranus 115→58 KB, Venus 120→63 KB,
  Saturn 95→63 KB, Jupiter 176→150 KB, Mars 257→232 KB, Mercury 552→527 KB.
- The decoder is the three.js r185 `meshopt_decoder.module.js` (29 KB, MIT),
  vendored next to the GLTF loader and loaded with it on first model request.
  Its WebAssembly needs `'wasm-unsafe-eval'` in `script-src`; that source
  allows WebAssembly compilation only and leaves inline and eval'd JavaScript
  under the hash list. Without it the models fail silently and the plain
  fallback globes stay.
- Re-encoding Mercury's texture was measured and rejected: q80 saves 11 KB,
  q60 saves 114 KB with visible loss on the only planet whose detail is its
  craters.
- Draco and KTX2 were not used: they need 200 KB+ of decoder and transcoder
  code for a smaller geometry gain than Meshopt already gives here.
- Checked on screen: Saturn (oblate globe and NASA rings), Ceres and Mercury
  load from the compressed files and look as before.
